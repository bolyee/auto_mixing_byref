# AutoMix

레퍼런스의 음색·다이내믹스를 목표로 보컬 EQ와 컴프레서를 자동 조정하는 웹 애플리케이션이다. 리버브 RT60·Wet은 수동 설정이며, 보컬 분리·반주 합산·마스터링을 선택할 수 있다.

## 실행

프로젝트의 기존 가상환경을 사용할 때:

```bash
bash run.sh
```

브라우저에서 `http://127.0.0.1:8000`으로 접속한다. 새 환경은 의존성을 설치한 뒤 `python main.py`로 실행한다. Dockerfile은 Python 3.10을 기준으로 하며 `docker build -t automix .`, `docker run -p 8000:8000 automix`를 사용한다. 새로운 환경에서의 설치·Docker 빌드는 별도 검증이 필요하다.

## 현재 구현 기준 (2026-10-22)

기준 코드는 `auto_mix 복사본 2`이다. 이전 실험 수치와 현재 코드의 재검증 결과를 구분한다.

| 항목 | 현재 설정·동작 |
| --- | --- |
| 보컬 전처리 | 44.1 kHz 모노, −6 dBFS 피크 정규화 |
| 보컬 EQ | 17밴드, 200 Hz–10 kHz, L2·스무딩 각각 0.1 |
| 보컬 최적화 | EQ·컴프 50회, 학습률 각각 0.05, 톤→EQ / CF→컴프 경사 분리 |
| 컴프레서 | threshold 학습, ratio 기본 10:1 고정 설정, attack 0.5 ms / release 120 ms / knee 4 dB |
| 수동 리버브 | RT60 0.1–4.0초, Wet 0–1, API 기본 1.0초·0.2; 파라미터 학습 없음 |
| 음색 평가·차트 | 내부와 같은 reflect STFT, 80개 Slaney 멜 필터, 필터 무게중심 기반 평가 대역, 평균 dB 정렬 |
| 최종 음색 오차 | 소프트 리미터 적용 후 출력의 내부 L_tone_raw = 화면 tonal_error |
| CF 분석 | 원본·레퍼런스 각각 최대 LUFS 10초 구간; 곡 전체 CF는 참고값 |
| 반주 합산 | 각 신호의 최대 LUFS 3초로 밸런스 조절, API 보컬 게인 기본 −2 dB |
| 마스터링 EQ | 15밴드, 20 Hz–10 kHz, L2·스무딩 각각 0.5, 학습률 0.05 |
| 마스터링 드라이브 | 학습률 0.1; EQ와 같은 외부 루프에서 각각 300회 갱신 |
| 마스터링 손실 | 톤→EQ, 리미터 출력 LUFS 차이 제곱·GR 페널티→드라이브 |
| 감쇄 제어 | 선택한 10초에 3.0 dB 초과 GR 페널티, 3.5 dB 기준 추가 가드; 전곡 상한 아님 |
| 추가 가드 | Adam 이후 최대 80회, 드라이브 0.25 dB씩 감쇠, 하한 −12 dB |
| 출력 실링 | 마스터링 샘플 피크 −0.3 dBFS; True Peak 적합성 별도 검증 |

보컬 신호 흐름은 STFT → EQ → iSTFT → 시간영역 컴프 → 선택적 수동 리버브 → 출력 소프트 리미터이다. 반주가 없으면 처리 보컬 자체를 마스터링할 수 있다. 분리한 레퍼런스 보컬은 보컬 처리 목표로, 업로드 원본 레퍼런스는 마스터링 목표로 사용한다.

마스터링의 300회와 보컬의 50회는 별도 단계이다. 마스터링은 전체 곡 평균 스펙트럼으로 EQ를 평가하고 선택한 10초에서 LUFS·GR을 평가한다. 보컬 화면 평가 방식 통일은 마스터링의 별도 분석 경로를 변경한 것이 아니다.

## 파일 구성

- `main.py`: 업로드 API, 처리 호출, 결과 응답 및 정적 파일 제공
- `pipeline.py`: 보컬 최적화와 렌더링, 내부·화면 결과 평가
- `modules.py`: EQ·컴프·리버브·리미터, 반주 합산과 통합 마스터링
- `losses.py`: 멜 톤 손실, CF 및 LUFS 측정, 감쇠 지표
- `separation.py`: torchaudio `HDEMUCS_HIGH_MUSDB_PLUS` 보컬 분리
- `static/`: 그래프, 비교 재생, 다운로드 UI
